# План миграции данных GoFuture

## 1. Notification

**Граница данных.** Перенести данные о состоянии доставки уведомлений из общей БД монолита в БД сервиса Notification. Обе БД используют PostgreSQL. Монолит продолжает передавать данные о поездках для отправки уведомлений. AS-IS C3 показывает кеш данных об устройствах в Redis. До копирования уточнить источник данных об устройствах и состав истории доставки для переноса.

| Этап                                             | Обработка уведомлений и запись данных                                                                                                                           | Миграция и проверка                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Подготовить БД сервиса Notification              | Компонент Notification в монолите и воркеры Celery продолжают обрабатывать уведомления. Данные о состоянии доставки по-прежнему записывают в общую БД монолита. | Копировать записи пакетами без остановки монолита. С начала копирования отслеживать изменения записей в общей БД монолита. Применять эти изменения в БД сервиса Notification.                                                                                                                                                                                                                                                       |
| Передать обработку и запись сервису Notification | Сервис Notification обслуживает синхронные запросы Booking и выполняет задачи из RabbitMQ. Сервис записывает данные о состоянии доставки в свою БД.             | Компонент Notification и воркеры Celery завершают начатую обработку уведомлений. Затем они прекращают запись данных о состоянии доставки. Новые задачи остаются в очереди RabbitMQ. Применить оставшиеся изменения в БД сервиса Notification. Сверить записи в обеих БД на одной транзакционной позиции. Проверить чтение и запись в БД сервиса Notification. Устранить блокирующие расхождения перед передачей обработки и записи. |
| Переключить получение сообщений на Kafka         | Сервис Notification получает сообщения о поездках из Kafka и продолжает записывать данные о состоянии доставки в свою БД.                                       | Переключать каждый сценарий отправки уведомлений, когда нужные для него сообщения доступны в Kafka. Для каждого сценария использовать один источник сообщений. Обработать оставшиеся задачи из RabbitMQ.                                                                                                                                                                                                                            |

**Целевое состояние.** Сервис Notification обрабатывает уведомления после передачи сценариев из монолита. Сервис хранит и изменяет данные о состоянии доставки в своей БД. После переключения автоматические проверки выявляют расхождения в данных. Хранить исходные данные для восстановления не менее года после успешного завершения всех миграций.

## 2. Pricing

**Граница данных.** Перенести правила ценообразования из таблицы `pricing_rules` общей БД монолита в PostgreSQL сервиса Pricing. Исходные записи брать из `pricing_rules`. Redis используется для кеширования этих правил.

| Этап                                      | Расчёты и запись данных                                                                                                                        | Миграция и проверка                                                                                                                                                                                                                                                                                                           |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Подготовить БД сервиса Pricing            | Компонент Pricing в монолите продолжает рассчитывать стоимость поездок и заработок водителей. Изменения правил записывают в общую БД монолита. | Копировать правила пакетами. С начала копирования отслеживать изменения в `pricing_rules` и применять их в БД сервиса Pricing.                                                                                                                                                                                                |
| Передать расчёты и запись сервису Pricing | Компоненты Booking и Driver в монолите обращаются к сервису Pricing. Сервис читает и изменяет правила в своей БД.                              | Кратковременно приостановить изменение правил и применить оставшиеся изменения. Сверить правила в обеих БД. Сравнить результаты расчёта стоимости поездки и заработка водителя на одинаковых входных данных. Переключить вызовы и возобновить изменение правил через сервис Pricing после устранения блокирующих расхождений. |

**Целевое состояние.** Сервис Pricing самостоятельно хранит и изменяет правила ценообразования. Booking и Driver используют его для расчётов. После переключения всех потребителей монолит прекращает обращаться к таблице `pricing_rules` и кешу правил. Исходные данные сохраняются по NFR-14.

## 3. Geography

**Граница данных.** Перенести геозоны из таблицы `zones` общей БД монолита в PostgreSQL сервиса Geography. Заполнить целевой индекс Elasticsearch актуальными координатами водителей. До выделения Driver данные о водителях поступают из монолита. На время миграции сохранить кеш геоданных в Redis монолита.

| Этап | Запросы и запись данных | Миграция и проверка |
| --- | --- | --- |
| Подготовить БД и геопоисковый индекс | Монолит продолжает обслуживать запросы, изменять геозоны и принимать обновления координат. | Копировать геозоны пакетами и синхронизировать изменения. Подтвердить источник актуальных координат и определить, как получать обновления во время загрузки. Использовать действующий индекс для начальной загрузки, если он содержит все координаты, необходимые для геопоиска. Применять к целевому индексу обновления, поступившие с начала загрузки. |
| Передать запросы и запись сервису Geography | Booking и Driver в монолите обращаются к сервису Geography. API Gateway передаёт ему обновления координат. Сервис изменяет геозоны в своей БД и обновляет координаты в целевом индексе. | Перед переключением кратковременно приостановить изменение геозон, применить оставшиеся изменения и сверить записи. Сравнить результаты геопоиска на одинаковых координатах. Проверить, что Booking получает маршруты от Geography, а Analytics в монолите продолжает получать метрики геопоиска. Под целевой нагрузкой подтвердить, что не менее 99% обновлений доступны геопоиску за пять секунд. Передать сервису обновления координат, принятые во время переключения. |
| Переключить кеш геоданных | Сервис Geography переходит с Redis монолита на Redis платформы. | Определить, какие запросы используют кеш геоданных, и проверить их под нагрузкой отдельно от запросов к Elasticsearch. |

**Целевое состояние.** Сервис Geography управляет геозонами, обновляет координаты в Elasticsearch и кеширует геоданные в Redis платформы. Монолит прекращает запись геозон и обновление прежнего индекса. Исходные данные сохраняются по NFR-14. Общий Redis монолита отключают после переключения всех его потребителей.
